How routing works

The right model for each prompt, in one call.

An easy question doesn't need your biggest model, and a hard one shouldn't go to your smallest. PromptLint decides per prompt, explains why, and tells you what you saved.

Read the prompt

One call to TypeSafe's Jev decision model rates how hard the prompt is (low, medium, high) and what kind of task it is (coding, writing, math, a quick fact…), with a probability for each. About 200 ms.

complexitytask_type

Pick the model

The strategy turns difficulty into the tier needed. Among your models that qualify, it takes the cheapest, unless another fits the task clearly better (Claude for code and writing, by default). A backup from another provider comes too.

cheapestbalancedquality

Send it, or just tell you

Connect your OpenAI, Anthropic, Gemini or OpenAI-compatible keys and /v1/route calls the model and returns the answer. No keys? You get the recommendation as JSON and call it yourself.

POST /v1/routefallback

Every decision comes with its reason.

The response names the recommended model, the backup, the tier the prompt needs, each model's task fit, and the saving against a baseline you choose, in dollars and percent.

If a prompt is so vague that any model would miss, the router says clarify first instead of spending money on a guess.

Your account page tracks it all: which models got your prompts, per API key, what you spent, and how much routing saved.

Built in: prompt lint

The cheapest call is the one you don't repeat.

A vague prompt doesn't fail loudly. The model guesses, you read the answer, and you pay again for the correction. The same call that routes your prompt also checks it, so you can fix the gaps before the first send.

A report card with every route.

  • A 0–100 score and the odds an LLM gets it right on the first try.
  • Eleven concrete checks: goal, context, format, audience, limits, conflicts… each with its probability.
  • Fix-it tips ranked by how many points they're worth, and a fill-in-the-blanks version.
  • Token counts and a cost range on every model, before you send anything.

Under the hood

One judgment call. Everything else is arithmetic.

PromptLint never asks a chatbot for its opinion. It asks TypeSafe's Jev, a System One decision model built to answer typed questions with calibrated probabilities, and then does the rest in ordinary, testable code.

Eighteen questions, one request.

Your prompt goes to Jev as {"prompt": "…"} together with every question at once: twelve yes/no checks ("Does prompt say what form the answer should take?"), five scales whose levels describe situations rather than degrees, and one task-type choice. Jev returns a probability for each, typically in about 200 ms.

The questions live in one YAML file, so tuning their wording never touches code.

# config/questions.yaml
has_output_format:
  instructions: Does `prompt` say what form the
    answer should take, such as a list,
    table, code, email, or word count?

specificity:  # score, 0–3
  criteria:
    - Generic request anyone could send
    - Names the topic but not the situation
    - Describes the goal; key details left
    - Names the exact situation and goal

Scored by weights you can read.

Each answer becomes a number from 0 to 1, flipped where lower is better (conflicts, ambiguity). A weighted sum gives the Lint Score: first-try success counts most (25%), then clarity and specificity (15% each).

Two hard caps keep it honest: contradictory instructions cap the score at 60, and an unclear task caps it at 40, however polished the rest looks.

2Token countertiktoken or provider count, in parallel<5 ms
3Scorerweights.yaml + caps + verdict<1 ms
4Cost engineprices.yaml × token range<1 ms
5Tip rulestips.yaml, ranked by weight × shortfall<1 ms

What the lint checks

Eleven checks, three meters, two scores.

Every check shows the probability behind it, so you can see how sure Jev is, not only whether it passed.

Task is clear 15%

Does it say what the assistant should actually do? Below 30% caps the score at 40.

Enough context 10%

Background the model can't guess: who you are, what you've tried, why.

Sets constraints 4%

Length, tone, scope, tools to use or avoid, or a deadline.

Says the output format 5%

A list, a table, code only, an email, a word count.

Names the audience 3%

Who the answer is for, or the level of expertise to write at.

No conflicting instructions 5%

"2,000 words" and "under 100 words" can't both be true. Above 70% caps at 60.

One task at a time tip

Several deliverables in one prompt? You'll get a tip to split or number them.

Includes an example info

Shown for reference. Examples help, but plenty of great prompts don't need one.

Needs live data info

If the answer depends on recent events, use a model with search or paste the data in.

States the goal PQS

Why you need it or how you'll use it, so the model can aim the answer.

Says what done looks like PQS

Checkable requirements: "return only the function", "end with a summary", test cases.

Two scores, side by side

Lint Score weights first-try odds most. PQS score weights clarity, specificity and completeness. Same answers, different formulas; the evals compare them.

First-try success 25%

The probability a capable assistant gives a complete, usable answer without questions or follow-ups.

Generic ↔ Specific 15%

From "anyone could send this" to "names the exact situation, inputs and goal."

Model-tier hint

From how much reasoning the answer needs: a small model is enough, mid-tier, or frontier, with the cheapest fit suggested.

Privacy & limits

What to know before you switch.

Your keys stay yoursSaved provider keys are encrypted and only the last 4 characters are ever shown. Keys sent with a request are used once and never stored. You pay each provider directly.
Not a prompt storePrompts and answers aren't saved unless an API caller opts in with store: true. Usage records keep a salted hash, the scores, the model used and the cost.
Savings are estimatesThey're measured on our 480 test prompts at list prices. Your mix of prompts decides your number, and the router assumes a cheaper model that's rated good enough really is. Try it on your own traffic with the calculator and the account page stats.
Not an oracleJev reads questions literally and can be nudged by text inside your prompt. Task-fit ratings are editable opinions, not benchmarks. Answers come back whole (no streaming yet).
