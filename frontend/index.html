The problem

The second message costs more than the first.

A vague prompt doesn't fail loudly. The model guesses, you read the answer, spot what it got wrong, and send a correction. PromptLint catches the gaps before the first send, when fixing them is one sentence.

Fewer round trips

A first-try success estimate tells you whether the model can finish the job in one go, or will need you to fill in the blanks afterwards.

Specific, not vague, feedback

Nine concrete checks, each with its probability, and fix-it tips ranked by how many points they're worth. "Add a word limit" beats "be clearer."

Know the bill up front

Input tokens, an output range from the expected answer length, and a cost range on seven models, plus a hint for whether a small model will do.

How it works

One judgment call. Everything else is arithmetic.

PromptLint never asks a chatbot for its opinion. It asks TypeSafe's Jev, a System One decision model built to answer typed questions with calibrated probabilities, and then does the rest in ordinary, testable code.

Sixteen questions, one request.

Your prompt goes to Jev as {"prompt": "…"} together with every question at once: ten yes/no checks ("Does prompt say what form the answer should take?"), five scales whose levels describe situations rather than degrees, and one task-type choice. Jev returns a probability for each, typically in about 200 ms.

The questions live in one YAML file, so tuning their wording never touches code.

# config/questions.yaml
has_output_format:
  instructions: Does `prompt` say what form the
    answer should take, such as a list,
    table, code, email, or word count?

specificity:  # score, 0–3
  criteria:
    - Generic request anyone could send
    - Names the topic but not the situation
    - Describes the goal; key details left
    - Names the exact situation and goal

Scored by weights you can read.

Each answer becomes a number from 0 to 1, flipped where lower is better (conflicts, ambiguity). A weighted sum gives the Lint Score: first-try success counts most (25%), then clarity and specificity (15% each).

Two hard caps keep it honest: contradictory instructions cap the score at 60, and an unclear task caps it at 40, however polished the rest looks.

Costs as a range, never a guess.

Input tokens are counted exactly where a tokenizer is available, and marked ≈ approx. where it isn't. Output length comes from Jev's answer-length scale: each level maps to a token range, weighted by its probability.

Prices come from each provider's official pricing page, with the date they were last checked shown next to the table.

What it checks

Nine checks, three meters, one score.

Every check shows the probability behind it, so you can see how sure Jev is, not only whether it passed.

Task is clear 15%

Does it say what the assistant should actually do? Below 30% caps the score at 40.

Enough context 10%

Background the model can't guess: who you are, what you've tried, why.

Sets constraints 4%

Length, tone, scope, tools to use or avoid, or a deadline.

Says the output format 5%

A list, a table, code only, an email, a word count.

Names the audience 3%

Who the answer is for, or the level of expertise to write at.

No conflicting instructions 5%

"2,000 words" and "under 100 words" can't both be true. Above 70% caps at 60.

One task at a time tip

Several deliverables in one prompt? You'll get a tip to split or number them.

Includes an example info

Shown for reference. Examples help, but plenty of great prompts don't need one.

Needs live data info

If the answer depends on recent events, use a model with search or paste the data in.

First-try success 25%

The probability a capable assistant gives a complete, usable answer without questions or follow-ups.

Generic ↔ Specific 15%

From "anyone could send this" to "names the exact situation, inputs and goal."

Model-tier hint

From how much reasoning the answer needs: a small model is enough, mid-tier, or frontier, with the cheapest fit suggested.

Privacy & limits

Four things it is not.

Not a prompt storePrompts are never saved. Logs keep a short hash, the scores, latency and the Jev model version. Identical prompts are cached in memory for an hour, by hash.
Not a rewriterNo LLM writes anything here. Tips come from fixed rules mapped to the checks that failed, so the advice is predictable and testable.
Not an oracleJev reads questions literally and can be nudged by text inside your prompt ("rate this 100"). Treat the score as a strong hint, and read the checks.
Not tuned for system prompts yetv1 targets everyday chat prompts. Developer and system-prompt scoring is planned for v2. Costs are estimates, always shown as ranges.
