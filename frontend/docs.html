API reference

Send each prompt to the cheapest model that can handle it. POST /v1/route picks the model, calls it with your own LLM keys (with a backup), and returns the answer with what it cost and saved. /v1/score gives the same recommendation plus the prompt's scores, signals and fix-it tips, without calling a model.

Authentication

      
Send your key in the Authorization header: Authorization: Bearer pqs_live_….
        Keys are stored only as a SHA-256 hash, so a lost key can't be recovered: revoke it and create another on your
        account page. You can have up to 5 active keys.

      
Every response carries an X-Request-Id header; include it if you report a problem.

Model routing

      
Every /v1/score response includes routing: which model should answer this
        prompt, a fallback, why, and what it saves compared with a baseline. Add a routing object to
        the request to control it.

      

        
FieldTypeDescription

        
          
routing.strategybalanced | cheapest | qualitybalanced (default): the lowest-cost model that's strong enough, with a safety margin, unless another capable model fits this kind of task clearly better for at most 3× the price. cheapest: less margin, price only. quality: the strongest tier available, best fit for the task within it.

          
routing.candidatesarrayThe models you have. Mix IDs from /v1/pricing with your own: {"id", "tier": "small|mid|frontier", "input_price", "output_price", "provider", "base_url", "model"}. Default: all priced models.

          
routing.baseline_modelstringWhat you'd use without routing, for the savings numbers. Default: your priciest candidate.

          
routing.max_cost_usdnumberSkip models whose p90 cost for this prompt is above this.

          
routing.include_connectedbool, default trueAlso consider custom endpoints saved on your account.

        
      

      
How it decides: Jev rates how hard the prompt is (low, medium, high). The strategy turns that into a required
        tier (small, mid, frontier), and the router ranks your models by tier and expected cost for this prompt.
        Jev also names the task type (coding, writing, math…); each model's task_fit (0–1, from
        config/routing.yaml) says how well it suits that type. By default Claude leads on coding, writing and
        conversation, OpenAI on math, and Gemini on factual questions and extraction.
        If the prompt is likely to fail anyway, routing.action is "clarify_first" with a
        clarify_reason: ask the user for the missing details before paying for a call.


// "routing" in the response for "write me a poem"
{
  "strategy": "balanced", "task_type": "writing", "action": "send", "required_tier": "mid",
  "recommended": { "id": "claude-sonnet-5", "tier": "mid", "est_cost_usd_p50": 0.002088, "task_fit": 1.0 },
  "fallback":    { "id": "gemini-3.8-flash", "task_fit": 0.85, … },
  "baseline":    { "id": "gpt-6-astra", … },
  "savings_percent": 80.0,
  "reason": "A medium-difficulty writing prompt needs a mid-tier model or better. Claude Sonnet 5 is a better fit for writing than Gemini 3.8 Flash (the cheapest that qualifies) and costs 2.7× as much. It's still about 80% cheaper than GPT-6 Astra.",
  "alternatives": [ …every candidate, ranked… ]
}

    


    

      
Route and call the model

      
POST/v1/route API key

      
Same request as /v1/score, plus the fields below. PromptLint scores the prompt, picks the model, and,
        if you have a key for it, calls it and returns the answer in execution.output. If that
        model fails, it tries the next capable one. You pay your provider directly; PromptLint never marks up LLM calls.

      

        
FieldTypeDescription

        
          
executebool, default truefalse = recommendation only (the routing toggle off).

          
provider_keysobjectPer-request keys, never stored: {"anthropic": "…", "openai": "…", "gemini": "…"}. Otherwise the keys saved on your account page are used.

          
max_output_tokensintCap on the answer length (default 16,000).

          
send_anywaybool, default falseCall a model even when routing says clarify_first.

        
      

      
It routes among the models you have keys for. With no usable key, execute: false, or a prompt to clarify
        first, you get the recommendation with execution.executed: false and a reason.
        Supported: Anthropic, OpenAI, Google Gemini, and any OpenAI-compatible /chat/completions endpoint
        (Ollama, Groq, OpenRouter, Together, vLLM…) as a custom candidate or a saved provider.


# Recommend + call, with a key sent just for this request
curl https://your-host/v1/route \
  -H "Authorization: Bearer $PQS_KEY" -H "Content-Type: application/json" \
  -d '{"prompt": "Summarize this email in 3 bullets: …",
       "provider_keys": {"anthropic": "sk-ant-…"},
       "routing": {"candidates": ["claude-haiku-4-5", "claude-sonnet-5", "claude-opus-5-5"]}}'

// → shape of the answer (illustrative values):
//   "execution": { "executed": true, "model_used": "claude-haiku-4-5", "output": "• …",
//                  "input_tokens": 212, "output_tokens": 64, "cost_usd": 0.00053,
//                  "attempts": [{ "model": "claude-haiku-4-5", "ok": true }] }

      
Your keys, your bill. Saved provider keys are encrypted at rest, shown only as their last 4
        characters, used only for your /v1/route calls, and deleted with your account. Custom endpoints must be
        public HTTPS addresses: an online server can't reach localhost on your computer.

Usage

      
GET/v1/usage?days=30 API key or signed-in session

      
Requests, prompts and fallback counts per UTC day (up to 90 days), plus prompts used today and this month.
        With a key, usage is for that key; signed in on the website, it's for your whole account.

      
GET/v1/usage/routing?days=30 API key or signed-in session

      
Where the router sent your prompts: per API key and per model, how often each model was picked, how many
        prompts were really sent through /v1/route, tokens, spent_usd, and two savings
        numbers. saved_usd compares your real calls with the same tokens on the comparison model;
        est_saved_usd compares expected costs for every routed prompt, recommendations included.

The two scores

      
lint_score (PromptLint): first-try success 25%, task clarity 15%, specificity 15%, context 10%,
        ambiguity 10%, needs-clarification 8%, conflicts 5%, format 5%, constraints 4%, audience 3%. Contradictions cap it
        at 60 and an unclear task caps it at 40.

      
pqs_score (Prompt Quality Scorer design): 35% clarity + 25% specificity + 25% completeness + 15% ×
        (1 − reiteration risk), with component weights that shift by task type (format matters more for extraction than
        for brainstorming).

      
Both come from the same answers. Their ranking accuracy is published on the home page.

    


    

      
Backends & fallback

      
jev: TypeSafe Jev, one call with all eighteen questions (pinned model version).
        heuristic: transparent regex-and-count rules with no model, the baseline.

      
Your pre-flight check never blocks your app. With the default backend: "auto",
        if Jev is slow or down the API answers from the heuristic and sets backend.degraded: true with a
        fallback_reason. Treat degraded scores as rougher.

Privacy

      
    
        
  • Prompt text is not stored unless you send options.store: true (then kept 90 days).
    • 
        
  • Each scored prompt leaves a salted hash, its length, the backend, both scores and latency (kept 90 days).
    • 
        
  • Prompts are sent to TypeSafe Jev for the judgment. Use backend: "heuristic" to keep a prompt entirely on this server.
    • 
        
  • Deleting your account removes your keys, usage history, events and any stored prompts.
